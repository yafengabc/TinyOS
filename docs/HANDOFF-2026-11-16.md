## 2. 共识：四条讨论结论（均已双方确认）

### 2.1 Phase A 顺序采纳，但 A-2 不是零风险

- A-1/A-2 优先、A-5 押后——顺序不变。
- **A-2 必须配 per-field `offsetof` 断言 + `mem/ps/stat` 输出比对**。原因：`kernel/syscall.c:509` 起 `SYS_MEMINFO` 等仍硬编码写用户内存偏移；`_Static_assert(sizeof)` 抓不到字段顺序写反。`struct stat` 只在 `user/lib.h:123`，内核侧另写一遍。
- **A-3 `exec_format` 不能跟着 A-5 押后**，它属于第二批。它是 P4 镜像格式与 LZ4TOS 版本化的唯一入口，越晚 loader 逻辑越长、特征测试越难写。
- 补充（本方）：A-1 里"board.conf 成为能力真相"不是零成本——不搬 `layout.c`、不生成头之前，事实从 4 处变 5 处，要到 B-1 才收敛。排期时别把它当纯校验项。

### 2.2 `wd_start` 不做，但不能只写"不做"

真正的缺陷不是缺统一超时 API，而是**用迭代次数当时钟**：

- `drivers/display/st7789/rp2350rv/lcd_st7789.c:148/163/170/198/405` 是 `1e6`/`5e6` 次
- `board/rp2350rv/platform.c` 十几处 `1e6`/`1e5`

同一个 `5e6` 在 150 MHz RV32 和 400 MHz P4 上真实时间差几倍，且这些等待多在持锁/关中断状态，SMP 上另一核被挡在锁外，下限不可控。

**落地要求**：
1. 把"有界"从迭代数改成毫秒上限（至少给新增代码立规矩，存量分批）；
2. 立规则"不在关中断/持锁状态做长等待"；
3. `wd_start(cb, ticks)` 移到 B-8，触发条件是网络/companion 的请求级超时，不是现在。

### 2.3 P4 第一阶段不是"一行串口"

"一行串口"只是 B-5 探针的**验收标准**，不是第一阶段全部。文档 §2 的范围是「片上 SRAM 窗口 + 单域 + PMP/保护 + UART/timer + 启动探针」。

- v1 终点：**同一套 `scripts/esp-c3/accept.py` 在 P4 上 24/24、`priotest` PASS**。
- PSRAM 可执行窗口、WiFi full stack、LP 调度都在门外。
- **止损点**：若 B-5 之后 PMP 做不到 4 KB 粒度保护，P4 v1 明确降级为"无用户保护"，记入 OPEN-ITEMS，不要硬做。

### 2.4 生成物三类已定死（`ac025f9`）

| 类别 | 例子 | 入库 | 规则 |
|---|---|---|---|
| 源文件 | `abi/syscalls.csv`、`board.conf` | 是 | 唯一真相 |
| 派生输出 | `build/gen/board_config.h`、生成的 syscall 头/表 | 否 | `go run ./cmd/tos gen` 从源文件重建；CI 可复现；不进 diff |
| 跨仓库快照 | goc32 的 `abi/syscalls.snapshot.csv` | 是 | 是 goc32 的**输入**不是产物；文件头记 `tinyos_commit` + hash |

以后"生成物"一词**只指派生输出**，避免再次误解。
