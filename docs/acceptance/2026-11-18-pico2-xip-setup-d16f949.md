## 现象

`build/tinyos-rpi-pico2.uf2` 刷进真正的 Pico 2：无反应、USB 不枚举。同一镜像刷
ATK（同一颗 RP2350A）6/6，说明镜像格式、PICOBIN 头、M33 flags、启动链本身没问题，
差异在**板级 flash 部件**。

## 对照证据

- MicroPython 的 RP2 端口在 `ports/rp2/CMakeLists.txt` 里设置
  `PICO_EMBED_XIP_SETUP=1 # to put flash into continuous read mode`；
- pico-sdk 的 RP2350 `crt0.S` 在 `PICO_EMBED_XIP_SETUP` 打开时，把
  `boot_stage2/boot2_w25q080.S` 拷到 SRAM 执行；该文件把 QMI 从 ROM 的保守模式
  （03h 串行读、CLKDIV=12）切到 **EBh + A0h 连续四线读、CLKDIV=2、RXDELAY=2**；
- 我们自己的 `platform.c` 注释早就写明：ROM 的 03h/CLKDIV=12 模式“采样延迟按
  clk_sys 周期计，在 150 MHz 下短 12.5 倍”；此前只在 flash 写完恢复 XIP 时处理了，
  启动路径没有处理。

所以根因假设：ROM 的保守 XIP 时序在 `pll_sys_init()` 升到 150 MHz 后，对
W25Q64JV 采样不足 → 切换后的第一次取指读到垃圾（#7 的 `PC=0xeffffffe`），
USB 永远没机会初始化。ATK 的 flash 部件恰好能容忍。

## 改动

```text
board/rp2350-generic/boot2_w25q080.S   pico-sdk boot2 的 ARM 部分（BSD-3，RPi），
                                       自包含常量，必须从 SRAM 执行
arch/arm/start.S                       _start 在 .data 拷贝之前：拷到 __boot2_ram、
                                       dsb/isb、blx 执行、再 dsb/isb
internal/build/build.go                chip == rp2350 && arch == arm 且板子要求时
                                       加 -DTOS_RP2350_BOOT2
internal/build/boardconf.go            board.conf 新键 xip_setup；未知值报错
board/rpi-pico2/board.conf             xip_setup = boot2-w25q080
```

**为什么是板级而不是芯片级**：用不用这套时序取决于焊的 flash 部件，不取决于硅片；
ATK 不设该键，因此它的镜像**逐字节不变**（sha256 对照通过）。以后确认 ATK 的部件
同样适用，再在它的 board.conf 打开。
