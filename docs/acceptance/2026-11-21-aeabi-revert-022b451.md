## 为什么是回退而不是保留

`1cd70da` 的做法是：`__ARM_ARCH_EXT_IDIV__` 时 `__aeabi_uidiv` 直接 `n / d`。
它只在 **编译器自己定义这个宏** 时生效。goc32 用自己的前端编译 `user/aeabi.c`，
预处理器不认识这个宏（`-E` 仍是 `tos_udiv32`），所以板上 div 仍是 1343 ms；而
如果强行给它补 `-D`，goc32 会把 `n / d` 翻成 `bl __aeabi_idivmod`，形成无限递归。

#45 改在正确的位置：goc32 的 Thumb-2 后端直接发 `udiv`/`sdiv`（余数用
`mul`+`subs`），ARMv6-M 仍走 EABI helper。这样在 IDIV 核上已经没有代码引用
`user/aeabi.c`，那个分支成了死代码兼递归陷阱，所以恢复成只有软件循环的版本。

用仓库内的 goc32 核对：

```sh
goc32 -target rp2350 -S bench/bench.c   ->  sdiv r2, r0, r1
goc32 -target rp2040 -S bench/bench.c   ->  bl __aeabi_idivmod
```

ARMv6-M（RP2040）需要的正是后者的软件循环，未受影响。
