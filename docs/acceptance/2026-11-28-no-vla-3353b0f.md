## 为什么去掉

VLA 的帧大小是运行期才知道的值，而帧检查、guard 尺寸、`TOS_STACK` 都是
编译期数字。一个 8 KiB 的 VLA 和 8 KiB 的固定数组对栈的破坏方式一样，但
编译器对前者没有任何数可以比较。要么在分配时逐页 probe，要么禁止——树里
没有任何程序用 VLA（T1 18/18 验证），所以先选禁止。

## 现在的行为

```text
$ goc32 -target esp32c3 -o build/vla.tos build/vla.c
goc32: build/vla.c: type errors:
  line 12: variable-length array "b" is not supported: its frame is only known
  at run time, so the stack check cannot see it; use a fixed-size buffer, or
  TOS_HEAP + malloc
```

clang 编译的用户程序（`tos build` / SDK 之外的路径）用同样的规则：

```c
char b[n];   /* -Wvla -Werror=vla: error: variable length array used */
```

固定数组照常：`char b[16]` 通过；需要动态大小的，用 `TOS_HEAP` 声明堆再
`malloc`，帧是常量。
