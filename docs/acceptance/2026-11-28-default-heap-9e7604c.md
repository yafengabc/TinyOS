## 为什么需要

窗口 = `span + 栈 + heap_ask + guard`，每一项都是 4 KiB 的整数倍，没有取整
空档。没有 `TOS_HEAP` 的程序 `heap_base == heap_end`，第一次 `malloc` 就返回
NULL——而且没有提示。帧审计解决了“单帧跨 guard”，但没有覆盖“用了堆却没声明”。

## 构建（clang）怎么做

1. 每个程序编译完后，看**它自己的** object（不含 common）：`.symtab` 里未定义
   符号落在 `malloc/calloc/realloc/sbrk/thread_create/co_create` 就认为用堆；
2. 这些 object 的 `.note.tos` 里若已有 type 2（`TOS_HEAP`）则不干预；
3. 否则生成一个 24 字节的汇编 note（`.section .note.tos,"a",@note`，与
   `lib.h` 的宏同构），随程序一起链接；构建日志打印
   `HEAP bin/<name>: no TOS_HEAP, default 8 KiB`。

## toscc 怎么做

- `user/heap.c` 加入运行时源列表——在此之前 toscc 程序里 `malloc` 链接直接
  报 `undefined symbol "heap_alloc"`，所以“默认堆”在 SDK 侧本来无从谈起；
- `lz4tos.PackHeap(elf, out, defaultHeap)`：ELF 的 `heap_ask` 为 0 时用它覆盖
  envelope 头的 heap 字段；显式声明优先；
- IR 里出现上述调用（`co_create` 也算）即认为用堆；
- `heap.c` 的对齐断言改成 `_Static_assert`，否则 toscc 无法解析该文件。

## 验证

| 场景 | 结果 |
|---|---|
| C3，临时 `huser.c`（malloc，无 `TOS_HEAP`） | 构建打印 `HEAP bin/huser`，note 8192，板上 `huser: malloc ok` |
| C3 默认镜像 | 无 `HEAP bin/` 行，镜像不变（树内 malloc 用户都声明了） |
| toscc `huser.c` | `hint 4096/0/8192` |
| toscc `TOS_HEAP(4K)` 的 `hdecl.c` | `hint 4096/0/4096`（声明优先） |
| `prot` | `TOS_HEAP(0)` note，heap 0，`prot heap` 仍在 brk 之后 fault |

临时程序不入库；C3 accept 42/42，T0/T1 18/T2 smoke 全过。

## 注意

- 8 KiB 是**下限**：两个 2 KiB 合作线程 + 块头约 4.1 KiB，够；需要更多仍要显式
  `TOS_HEAP(n)`；
- 用了堆的程序会因此多 8 KiB 窗口（这是默认值的成本）；
- `thread_create`/`co_create` 本身 malloc 栈，所以它们也算“用堆”；
- `TOS_KTHREADS` 的 `-Oz` 下 toscc 是否解析得动未验证（本轮 toscc 测试是默认
  配置，kthreads 关闭）；构建侧（clang）不受影响。
