notes:
- Root cause: emit_helpers() emitted the capture helper between L_pin (the
  R_PRINTV entry, which falls through into the printer) and L_picommon (the
  printer).  So printf("%d") ran capture() with the value as a "path", got -1,
  and returned before any digit was written.  The literal text around the
  conversion comes from R_PRINTS (a direct write syscall), which is why an
  empty number looked like "the format lost its value".
- print() (R_PRINT -> L_pi, an explicit branch to L_picommon) was unaffected,
  and the corpus only used print() for integers, so nothing caught it.
- Found while writing the MicroPython/pvm/rvm/rcc benchmark: its kernels print
  the elapsed ms and the checksum with printf("%d").
- The fix moves the capture helper above the L_pi/L_pin pair so nothing is
  emitted between L_pin and L_picommon; the printed text and code size are
  otherwise unchanged.
- RV32 never had the bug: rv32.inc already emits the capture helper first.
