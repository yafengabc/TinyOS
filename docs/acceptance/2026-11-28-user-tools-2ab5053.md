## 命令

| 命令 | 行为 |
|---|---|
| `kill [-9|-STOP|-CONT] pid...` | `SYS_SIGNAL` 的命令行；默认 SIGKILL（和 ^C 同一个信号） |
| `cp <src> <dst>` | create 会截断，所以同文件复制直接拒绝 |
| `tee [-a] [file...]` | 先写 stdout，最多 8 个文件；`-a` 打开后 seek 到尾部 |
| `head [-n N] [file...]` | 无文件读 stdin，可以接管道 |
| `tail [-n N] <file>` | 文件专用；记住最后 N+1 个行首偏移，内存固定 400 B |
| `grep [-i] [-n] [-v] pat [file...]` | 子串匹配；支持合并短选项（`-iv`）；超长行按前 511 B 匹配 |
| `stat <path>...` | 类型 + 字节数（这个 FS 没有 inode/时间戳） |
| `du [path...]` | opendir/readdir 递归求和；最多 3 层，避免 4 个目录流耗尽 |

`kill()` 只是 `tos_sys2(SYS_SIGNAL, pid, sig)` 的包装，ABI 没有新增系统调用。

## C3 实测

刷入当前默认镜像（`esp32c3-generic`），`accept.py` **42/42**，然后：

```text
tos> kill                     -> usage: kill [-9|-STOP|-CONT] pid...   (exit 2)
tos> kill 9999                -> kill: 9999: no such task              (exit 1)
tos> kill -BOGUS 1            -> kill: unknown signal -BOGUS           (exit 2)
tos> kt                       -> spawn pid=3
                                 stop=0
                                 cont=0
                                 kill=0
                                 kill-again=-1
                                 wait=137
tos> cp /readme.txt /u.txt    -> ok；cat /u.txt 与原文一致
tos> head -n 3 /readme.txt    -> TinyOS / ====== / 空行
tos> tail -n 3 /readme.txt    -> 最后两行与 readme 一致
tos> grep -n TinyOS /readme.txt  -> 1:TinyOS
tos> grep -iv tinyos /readme.txt -> 其余行（大小写折叠 + 反选）
tos> cat /readme.txt | tee -a /a.txt
tos> wc /a.txt                -> 38 245 1404（echo 的 2 B + readme 的 1402 B）
tos> stat /a.txt              -> file, 1404 bytes
tos> du /tests                -> 4491 /tests
tos> du /                     -> 169009 /
```

`kt` 是临时的验证程序：`exec("/bin/sleep")` 后依次 SIGSTOP、SIGCONT、SIGKILL，
再 `wait()`。SIGKILL 的退出码 137 = 128+9。

## 一个在板上抓到的 bug

`du` 最初用 `%lu` 打印总数；用户态 `printf` 不支持 `l` 修饰，`%s` 于是把数字
当指针，`du /tests` 以 `load access fault ... (address 0x118b)` 结束。改成
`%u` 后正常。这也是为什么这批工具都放在板上跑了一遍再提交。

## 芯片基线的空间

`rp2350-generic` / `rp2350rv-generic` 两个 bring-up 基线用的是 **RAM 里的
300 KiB 内嵌文件系统**；加上这 8 个工具后 littlefs 报 `No more free space`
（把 FS 加到 452 KiB 会溢出 512 KiB SRAM）。处理：两个基线额外排除 demo 和
probe（板级镜像保留它们），文件系统大小不变。`boardconf_test.go` 的排除清单
fixture 同步更新，T1 恢复 18/18。
