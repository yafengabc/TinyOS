## 体积

`size` 的 `text` 列（含 `.rodata` 合并段）/ `Total`，以及 UF2 文件大小：

| 镜像 | 版本 | `.text` | `Total`（text+data+bss） | UF2 |
|---|---|---|---|---|
| `atk-dnr2350am-smp`（M33） | `-O2` | 200,064 | 341,836 | 3,146,240 |
| 同上 | `-Oz` | 86,128 | 225,112 | 2,097,664 |
| `atk-dnr2350am-rv32-smp` | `-O2` | 132,304 | 248,058 | 3,146,240 |
| 同上 | `-Oz` | 92,704 | 208,128 | 3,146,240 |

变化：

- **M33**：`.text` **−113,936 B（−57.0%）**，Total **−116,724 B（−34.1%）**；
  `.bss` 两版都是 137,024 B。
- **RV32**：`.text` **−39,600 B（−29.9%）**，Total **−39,930 B（−16.1%）**；
  `.bss` 两版都是 110,016 B。

UF2 大小包含文件系统/打包填充，不能直接当内核体积；M33 的 2 MiB→3 MiB 是打包后的
整档大小，真实差值看 `.text`/Total。

## 性能（只有 O2 可测）

每项三次，UART0 COM14，命令原文：

```sh
python build/run_bench.py COM14 coremark 60 build/opt/.../coremark-N.raw
python build/run_bench.py COM14 "smpbench 1250000" 20 build/opt/.../smpbench-N.raw
```

| 镜像 | 指标 | 三次结果 |
|---|---|---|
| M33 `-O2` | CoreMark | 482 / 482 / 482 iter/s |
| M33 `-O2` | smpbench 1250000 | single 37 ms；dual 35+38 / 35+37 / 35+37；speedup 1.94 / 2.00 / 2.00x |
| RV32 `-O2` | CoreMark | 447 / 421 / 421 iter/s |
| RV32 `-O2` | smpbench 1250000 | single 52 / 52 / 53 ms；dual 54 / 54 / 54 ms；speedup 1.92 / 1.92 / 1.96x |

`-Oz` 的性能**没有数据**：两版都进不了 shell，见下。

## `-Oz` 启动失败（阻断项）

- **M33 SMP**：UART0 输出到 `[D] cpu0` 和 `TinyOS/RP2350 ...` 后反复重启，
  没有 `[E] usb`、没有 CDC、没有 `tos>`。日志 `build/opt/Oz/boot6s.raw`。
- **M33 UP**：同样卡在 `[D] cpu0` 后循环。日志 `build/opt/Oz-up/boot8s.raw`。
- **RV32 SMP**：启动轨迹走到 `[u4] pullup`、`[U] usb hw=1 cfg=1`、banner
  `TinyOS/RP2350 rv32 ... usb-cdc=up`，随后 UART0 静默；CDC 在设备树里出现，
  但打开被拒/无 shell。日志 `build/opt/Oz-rv32/boot15s.raw`。

所以 `-Oz` 在 M33 上目前**不是“更慢”而是不能用**，性能/功耗的取舍无法评估。
`docs/OPEN-ITEMS.md` §26 记了这一条；`#56` 里“M33 的 -Oz 与 P1 未做”现在有了
具体失败现象。没有改任何源码、没有为了变绿动测试或判据。

板子最终恢复为 `atk-dnr2350am-rv32-smp` 的 `-O2` 镜像（`UART0` 正常进 shell）。
