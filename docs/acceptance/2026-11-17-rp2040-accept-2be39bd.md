## 执行的命令与结果

RP2040 只能物理按 BOOTSEL（CH343 的 DTR/RTS 未接复位），`autoflash.py` 在已挂载的
`F:` 上一次性刷写并抓启动日志：

```sh
go run ./cmd/tos build -target rp2040smp
python scripts/rp2040/autoflash.py --uf2 build/rp2040smp.uf2 --port COM19 --probe --grab 12
python scripts/rp2040/heartbeat.py --port COM19 --target rp2040smp
python dd1000.py COM19 rp2040-dd1000 1000        # 1000 x (dd of=/x bs=512 count=1 ; rm /x)
python scripts/rp2040/heartbeat.py --port COM19 --target rp2040smp   # after soak
```

### 判据 4（可选）：goc32 产 V0 `.tos` 上板执行一次

```sh
# goc32 默认产 RV32；RP2040 是 ARM，必须 -target rp2040
cd goc32 && go run . -target rp2040 ../user/hello.c -o ../build/goc32-hello-rp2040.tos
# 1444 字节（含信封 1472），LZ4TOS, hdr[6]=1 -> V0
tools/tosput/tosput-cli.exe COM19 build/goc32-hello-rp2040.tos /bin/goc32hello
# verified: 1472 bytes, crc32 7c3f8568
```

板上执行：

```text
tos> goc32hello
hello from ring 3!
pid=556 argc=1 uptime=327167 ms
  argv[0] = "goc32hello"
tos>
```

顺带确认：先用默认 `-target rv32` 的产物上传时，内核**正确解开了 V0 LZ4TOS 信封**，
只在 ELF machine 检查处拒绝（`machine 243 (rv32)` vs `machine 40 (arm)`）——这正是
B-3 之后 V0 容器仍被接受、按 ISA 拒绝的预期行为。

## 没跑 / 未通过

- **自动 BOOTSEL**：RP2040 无自动路径（CH343 DTR/RTS 未接复位），本轮靠已挂载的
  BOOTSEL 盘 + `autoflash.py`；未做物理按键流程的重复演练。
- **C3 / RP2350**：不在本 issue 范围；RP2350 由 `2026-11-17-b2b-park-merge-rp2350.md` 覆盖。
- **RP2040 1000 轮的中途**：第一次跑到 400 轮时为让路 `tosput-cli` 手动中断，随后从头
  重跑完整 1000 轮；本卡记录的是完整那一轮。
