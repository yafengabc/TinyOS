| 程序 | 板上输出 | 判读 |
|---|---|---|
| `t1-capture1` | `0` | 数字、无 fault ✓ |
| `t1-dir1` | `1` / `0` / `-1` | isdir /bin、普通文件、不存在路径 ✓ |
| `t1-exec1` | `hello from ring 3!` / `pid=50 argc=0 uptime=61432 ms` / `0` | 子进程输出 + pid，收尾 0 ✓ |
| `t1-file1` | `1` `24` `0` `0` ``(空行)`` `0` `0` | 与 QEMU mps2 基线 `1 24 0 0` **逐字一致**（见下） |
| `t1-native` | `6765` | 无 fault ✓ |
| `t1-benchfib` | `87` / `46368` | 87 ms，结果 46368 ✓ |
| `t1-benchloop` | `1764` / `-2014260032` | 1764 ms，结果 -2014260032 ✓ |

**`file1` 的第 5 行是空行，与 mps2 基线一致、不是 Thumb-1 回归**：手工在板上跑
`/bin/t1-file1` 的原始输出是 `1\r\n24\r\n0\r\n0\r\n\r\n0\r\n0\r\n`——`write("hello",5)`
返回 24、`read` 返回 0，所以文本行为空。`2026-11-21-thumb1-backend-6c24de3.md` 在
QEMU mps2 上记录的是同一个 `1 24 0 0`，两个平台行为相同。这是既有 fs 语义
（与本 issue 的代码生成无关），**建议另开一条 issue 追**：`write` 返回 24、
读回 0 字节，看起来不对。

## 刷机与端口细节（可复现）

- `python scripts/rp2040/autoflash.py --uf2 build/tinyos-rpi-pico.uf2 --watch`：
  盘上复制 4 MiB 用 23.2 s，`drive ejected after 0.75s`；该脚本默认去开 COM19（UART0
  的 CH343，本次未接）所以它自己报 FAILED，**刷机本身成功**。
- 刷完后 CDC 一度 `PermissionError(13)`（PowerShell `SerialPort.Open()` 同样被拒），
  物理拔插一次 USB 后恢复正常；这是 Windows 侧端口未释放，不是固件问题。
- 板上 `/proc/flash` 记录该板 flash 为 16 MiB（`flash_bytes = 2m` 只用了前 2 MiB）。

RP2040（ARMv6-M / Thumb-1）**上板通过**：心跳 6/6、37 项严格比对全过、7 个观察项
无 fault、输出与 QEMU mps2 基线一致。#38 的 T3 门槛满足。
