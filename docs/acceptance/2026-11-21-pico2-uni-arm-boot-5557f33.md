## 现象（修复前）

单核 ARM 镜像刷入后 **USB 从不枚举**，UART0 上是约 4 秒一轮的复位循环：

```
[A] clocks+reset ok  clk_sys=00b71ee8
...
[E] usb hw=1 cfg=0 stage=0 clk_sys_khz=000249f0 clk_usb_khz=0000bb81
   （然后复位，从不出现 banner/shell；[PREV] 全 0）
```

## 根因

`plat_init()` → `plat_board_init()` 里的 JEDEC RDID 探测（`rp2350_flash_detect_jedec`）
写 `QMI_DIRECT_CSR` 时只写了 `EN | ASSERT_CS0N`。**CLKDIV 是这个寄存器的字段，复位值是 6**；
不写它等于把 flash 时钟分频设为 0，即 SCK = clk_sys = 150 MHz，这颗芯片在这个频率下不回应。
于是 `RXEMPTY` 永远不清，每字节两次有界等待各跑满 `qmi_spin_limit()`（约 1e6 次，实测每次
约 0.4 s），整个探测拖到数秒。它发生在 **XIP 关闭窗口内、tick 存在之前**，而看门狗只由
tick 喂，所以 2.1 s 后看门狗直接把启动踢掉——这正是"没有 banner、没有 fault 记录"的形态。

定位方法：ARM 端补 `plat_boot_stage()`（此前只有 RV32 端实现），把 kmain 阶段写进 .noinit
并在下一次启动打印 `[PREV] ph=NN`；再在探测内部用 RAM 常驻的原始 UART 单字节标记，
得到 `1234` 后停在 CS 拉低之后、循环之内，直接指向这段代码。

## 修复

1. 写 `QMI_DIRECT_CSR` 时保留 CLKDIV（复位值为 6），退出时**恢复原寄存器值**而不是写 0
   （写 0 同样会清掉分频）；
2. 有界等待从 `qmi_spin_limit()`（约 1e6）降到 20000 次：这颗芯片要答就是微秒级，
   不答也必须快速失败——探针整体从数秒降到约 20 ms。容量随后来自 ROM 的 FLASH_DEVINFO
   （`/proc/flash` 一直报的 8 MiB 就是这个来源）；
3. ARM 端 `plat_boot_stage()`：一次 .noinit 存储（不读寄存器——RV32 环形日志自己的注释
   记录了这些读会干扰被测的启动），下一次启动以 `[PREV] ph=NN` 报告，并在每个阶段喂狗
   （看门狗在时钟树起来前就上膛，而只有 tick 喂它）。

## 遗留（另案）

单核镜像的心跳第 3、6 项仍失败，原因是**控制台输出在约 192 字节处被截断**，与启动无关：

```
$ ls /bin
... coremark          ← 停在这里，没有后续条目，prompt 也没回来
$ crash
about to execute an illegal instruction...
[pid 10] UsageFault at 0x20020076
  cfsr=... sfar=...     ← 同样截断
```

SMP 镜像没有这个现象。已单独立案追踪（控制台 TX 截断），#42 的"到不了 USB 枚举"
这一条本卡即可关闭。
