## 加了什么

| native | 语义 |
|---|---|
| `yield()` | 让出一个调度轮次，返回 0；不再受 1 ms tick 量化 |
| `ready(fd)` | 一次非阻塞 poll：可读返回 1，否则 0 |

实现路径沿用现有 `NATIVEC`（id ≥ `NAT_OPEN`）：

- `csc`：native 表两项（`yield` 0 参、`ready` 1 参，都有返回值）；
- `rvm`：`R_NATIVEC` 分支调用 `yield()` / `poll(&pf,1,0)`；host 构建有 stub，
  所以桌面测试仍能跑；
- `rcc`：`emit_native_argbuf` 在 rv32 / thumb2 / thumb1 上构造 8 字节
  `struct pollfd`，发 `SYS_POLL`，返回 `revents` 低字节；
- 内核不变：`SYS_YIELD`（13）和 `SYS_POLL`（37）本来就有。

## 为什么是单 fd

csc 没有结构体指针、结构体里也不能放数组，完整 `poll(fds,n,timeout)` 的 ABI
在脚本里没法舒服地表达。`ready(fd)` 覆盖控制台（fd 0）和 pipe/普通文件
（`open()` 得到的 fd）；需要超时就自己用 `uptime()` 循环。

## 仍不做

- 完整 `poll`（多 fd/超时）与 `yield` 之外的协程能力；
- 函数内任意点挂起（那需要状态机变换或栈式协程，前面讨论过）。
