## 结构

- `board/rpi-pico/platform.c`：`#ifdef TOS_USB_PUMP` 下 `usb_pump_task()`
  （`usb_cdc_poll(); replug/trace; process_ktask_sleep(1);`）与 `plat_start_tasks()`
  （`process_ktask_create("usbpump", ..., 4096, 0, 0)`）。
- tick 里的 `usb_cdc_poll()` 与两个请求处理改为 `#ifndef TOS_USB_PUMP`：特性开着时
  中断上下文完全不碰控制器。创建失败就没有任何 owner（控制台静默），与 RP2350
  的严格模式一致。
- `board/rpi-pico/board.conf`：`features = ..., kthreads, usb_pump`。

## 板侧要跑的（§22 清单）

1. 刷 `rpi-pico` / `rpi-pico-smp`（现在默认就是线程泵），启动看
   `[usb] pump thread pid N on cpu 0`，`cat /proc/ktask` 有 `usbpump` 与 size/used。
2. `accept.py`（CDC，2e8a:000a），21 KiB `cat` 两轮逐字节一致，heartbeat 6/6，
   `crash` 后提示符回来。
3. kthreadtest（现在默认在镜像里）：三探针 + 默认 0 failure。
4. 回退对照：`usb_pump = false` 的镜像仍走 tick 泵，确认两种模式都正常。
