## 执行的命令与结果

```sh
# 1) 构建（当前 HEAD + 工作区注释改动）
go run ./cmd/tos build -target rpi-pico2-rv32-smp        # build ok -> kernel-rpi-pico2-rv32-smp.elf

# 2) 烧写 + 冒烟（板子当时跑的是 rpi-pico2-smp ARM 镜像，用 UART0 发 Ctrl-D 进 BOOTSEL）
python scripts/rp2350/flash.py --uf2 build/tinyos-rpi-pico2-rv32-smp.uf2 \
    -p COM19 --uart-port COM19 --boot-uart COM19 --smoke
# 7/7 checks passed；启动行 `TinyOS/RP2350  rv32  uart0=115200  usb-cdc=up`、`[cpu1] secondary ready`

# 3) 测速 5 轮
python scripts/rp2350/dd_stress.py -p COM19 --target rpi-pico2-rv32-smp --rounds 5
# DD OK 5/5，1.0 rounds/s → 30 分钟 ≈ 1800 轮

# 4) 正式压测（32 KiB/轮，写+读回校验+rm，约 57.6 MiB 累计写入）
python scripts/rp2350/dd_stress.py -p COM19 --target rpi-pico2-rv32-smp --rounds 1800
# 30m37s，round 1800/1800 ok=1800，DD OK 1800/1800，exit=0
```

判定依据：

- **1800/1800 每轮读回校验通过**，没有 `DD FAIL`、没有坏 pattern、没有写错误；
- **`uptime` 1879 s > 压测 1837 s** → 30 分钟里没有复位（板子没自己重启，也没有被
  看门狗重启）；
- **`free` 的 kernel heap 只动了峰值水位**（used 0 / peak 1792），tasks 400 KiB 与
  压测前同量级 → 没有窗口或段泄漏；
- **`df` 回到 4% 占用**（used 364 KiB ≈ 镜像自带内容，free 7,491,584）→ 1800 轮
  写入的文件全部被 `rm` 回收，没有文件堆积；
- 结束后 shell 仍应答、两个 hart 都在 `rv32imac` 150 MHz。

## 备注

- 这块板是 **8 MiB W25Q64** 克隆板（官方 Pico 2 是 4 MiB W25Q32），`df` 总量
  7,864,320 = 8 MiB − 512 KiB，与 `board/rpi-pico2/board.conf` 的 `flash_bytes = 8m`
  一致。
- 压测走 UART0 而不是 CDC：CH343 是独立芯片，长跑期间不会因为 USB 枚举/流控问题
  干扰判据；CDC 只在 smoke 里确认过一次。
