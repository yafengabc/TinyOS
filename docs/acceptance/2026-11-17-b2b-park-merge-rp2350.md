## 落地的是什么

`board/rp_park.h` 现在拥有 park 的**整套**序列，不再只是状态和握手顺序：

```c
#define RP_PARK_OWNER_TAKE(s, spins_limit)  /* 屏蔽 IRQ → begin → wake →
                                               等本代 ack → 超时 release+wake+恢复 */
#define RP_PARK_PARKED_LOOP(s, spins_limit) /* parked=1 → 屏障 → 每轮 ack+喂狗 → parked=0 */
```

两份都是宏而不是函数：parked loop 在 XIP 关闭时从 SRAM 运行，必须展开进调用者的
`.data.ramfunc` / `.data.flash_ram` 段；函数指针 hook 会回调进 flash，正是这套协议要
避免的总线错误。板级在 include 前只定义差异：

| hook | rp2040 | rp2350 | rp2350rv |
|---|---|---|---|
| `RP_PARK_WDT_TICK` / `RP_PARK_OWNER_TICK` | 空 | `wdt_feed()`（+ 诊断） | `wdt_feed()` |
| `RP_PARK_STOP_FOREVER` | 空 | `g_core1_stopped` 后长驻 | 空 |
| `RP_PARK_PARKED_DIAG` / `PREPARE` / `ACKED` / `TIMEOUT` | 仅 timeout 提示 | `g_park_*` 组 | `g_pk_*` 组 |
| 屏障 / wake / IRQ 屏蔽 | 头文件按 ARM/RV32 选择 | | |

## 等价性：对象级

`.data` 段（RAM 中的 park loop，以及内联进 `plat_block_erase/write` 的 owner）
在三块板上与改前**逐字节相同**：

```text
rp2350smp   .data sha256 AB855C65…   base AB855C65…   IDENTICAL
rp2350rvsmp .data sha256 0d4d5b40…   base 0d4d5b40…   IDENTICAL
rp2040smp   .data 代码相同（仅一处指向 .text 的常量因布局偏移）
rp_flash_park_loop / plat_flash_park_poll 反汇编：三块板均 IDENTICAL
符号名 793 个：完全一致（无函数新增/删除）
```

保留符号构建还显示：`.text` 比改前小 10–12 字节（`TOS_KEEP_SYMS=1` + `objcopy`），
差异落在 `.text`/`.rodata` 里的地址常量与布局，不在 park 代码——`.data` 的逐字节相等
才是这条判据的核心证据。
