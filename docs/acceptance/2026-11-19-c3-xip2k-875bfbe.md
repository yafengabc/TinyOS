What changed
------------
1. XipFlashBase used to mean both "the 64 KiB MMU page the boot stub maps" and
   "the flash offset of the code blob".  They are now separate:
     XipMapBase   - flash page mapped at 0x42000000 (64 KiB aligned)
     XipFlashBase - flash offset of the first code byte (may be inside it)
   The linker places .text at 0x42000000 + (XipFlashBase - XipMapBase), the
   packer lays the blob out from that VMA, and start.S maps XipMapBase.
   The default board.conf still sets xip_flash_base = 0x10000 with no
   xip_map_base, so XipMapBase = XipFlashBase and the old layout is bit-for-
   bit unchanged (default image: 148,304 B, flash end 0x24350, mmu[0]=1).

2. New [build] keys xip_code_offset and xip_map_base, with validation:
   map base must be 64 KiB aligned, code offset must be inside the 56 pages
   the stub maps.  Two opt-in configs use them:
     configs/esp32c3-xip2k.conf       no WiFi, -Oz
     configs/esp32c3-wifi-xip2k.conf  WiFi + net, -Oz
   Both set xip_code_offset = 8192 (0x2000), xip_map_base = 0.

  `dd` prompt timeout in the same cycle; the standalone dd/rm rounds above
  pass.  Not hidden or waived: the no-WiFi 20/20 soak is the XIP stability
  result, and the WiFi py limitation is recorded here.
