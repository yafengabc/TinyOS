## 1. 决定

RP2040 上 **HardFault / panic 的报告只送 UART0**，USB CDC 镜像在打印期间关闭。

理由（板上已量过，见 `docs/OPEN-ITEMS.md` §5c）：M0+ 的 HardFault 固定在所有
可配置 IRQ 之上，故障处理器活动期间
- USBCTRL 的 IN 完成中断进不来 → 已交给端点的那一个包之后就停了；
- SysTick 也进不来 → CDC 环里的字节没人搬。

于是 CDC 镜像只能收到半份报告，端口随后还要重开。UART0 不需要中断：控制器按时钟
把 FIFO 里的字节移出去，整份 dump 都能到。

CDC 的 TX 环也在同一轮里**回到 256 B**，背压改由板级 `plat_console_can_take()`
提供（与 RP2350 同款）：环满时 `console_write_some()` 返回短计数、`write_all()` 让出、
1 kHz 的 tick 把环泵走。**按文件大小定环不可持续**——1536 只是刚好装下
`cat /readme.txt`（1402 B，CRLF 后 1439 B）；下一个 readme 写 10 KB 就没用了。

## 2. 改了什么

| 位置 | 内容 |
|---|---|
| `kernel/plat/console.h` | 新增 `void plat_console_mirror(int on)` 的契约说明（板子有第二路 sink 时才实现） |
| `kernel/console.c` | 弱默认空实现；`panic()` 在打印前 `plat_console_mirror(0)`（之后不恢复，机器已死） |
| `arch/arm/platform.c` | 用户故障转储前 `(0)`、`process_exit()` 前恢复 `(1)`，让之后的提示符两路都能看到；内核故障分支 `(0)` 后直接 panic |
| `board/rpi-pico/platform.c` | 实现钩子（`g_cdc_muted`），`plat_console_putc()` 在置位时不调 `usb_cdc_putc()`；新增 `plat_console_can_take()`，把 CDC 环的剩余空间报给 console 写路径 |
| `drivers/usb/rp2040/usb_cdc.c` | `USB_TX_Q` 1536 → **256**：环只是一次泵间隔的缓冲，写者由 `can_take` 节流 |
| `scripts/rp2040/accept.py` | CDC 控制台：`fault isolation` 记为 skipped（仍要求提示符返回、无 KERNEL PANIC）；UART0 保持严格检查 |

其它板不实现该钩子 → 弱默认空实现，M33（Pico 2 / ATK）的 CDC 转储行为不变。

## 3. 板上复验（交板主）

1. **UART0（严格）**：`accept.py -p <uart>` 的 `fault isolation` 仍应 PASS，且能看到
   完整 HardFault dump（`[pid N] HardFault at 0x...` + 寄存器 + 提示符）。
2. **CDC（新行为）**：`accept.py -p <cdc>` 的 `fault isolation` 显示
   `fault isolation (skipped: dump is UART0-only)`；同一时刻 UART0 上是完整 dump。
   关键点：**CDC 端口在 crash 之后不再需要重新打开**，提示符会自己回来。
3. **panic**：触发一次内核 panic（例如故意坏掉一个镜像），UART0 有完整报告，
   CDC 上不应出现半份报告。
4. 顺带看一眼长输出/`ls /bin` 仍然完整（mute 只在 fault/panic 期间置位）。

## 4. 一致性：为什么环能回到 256

RP2040 原来没有 `plat_console_can_take()`（弱默认 = "永远收得下"），所以
`console_write_some()` 从不返回短计数，环被迫去装下整段输出——这才有 1536。现在板级
按 RP2350 的契约报环剩余空间：

```
write() → console_write_some() → plat_console_can_take(1 或 2)
       环满 → 返回已写字节数 → write_all() yield() → 下次 write() 重试
       tick 每 1 ms 把环泵进 TinyUSB
```

于是环只需覆盖"两次泵之间"的产出（一次泵最多 256 B/ms），文件多大都一样：
10 KB 的 `cat` 只是多 yield 几次，不再需要更大的环。两个端口现在是同一套逻辑
（RP2350 环 256、RP2350RV 报 TinyUSB FIFO、RP2040 报环），差别只在泵的入口
（PendSV / U-mode 返回 / tick）。

## 5. 未做的事

- RV32 端口（C3 / RP2350RV）的故障转储没有接这个钩子：那边不存在 M0+ 的
  "HardFault 高于所有 IRQ" 约束，CDC 转储工作正常，不动。
- panic 之后的 Ctrl-D：同一轮已补上——`bootsel_poll_uart()`（panic 自旋里由
  `g_panic_poll` 反复调用）自己调 `bootsel_enter_rom()`，不再依赖 tick；见
  `docs/RP2040-BOOTSEL.md` §6。
