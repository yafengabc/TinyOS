## 复现（修之前）

```text
kernel/ramdisk.c:637:30: error: call to undeclared function 'hash_path';
ISO C99 and later do not support implicit function declarations [-Wimplicit-function-declaration]
tos: CC failed: exit status 1
```

同一棵树、同一个 config，只把 `kernel/ramdisk.c` 退回 `0460c3e` 就复现；换回修复版即通过。
说明不是构建器或工具链的问题。

## 修法与判据

```c
/* 无条件；unlink_locked() 仍是 #ifndef TOS_LFS_RO */
static uint32_t hash_path(const char *s) { ... }
```

选"移出保护块"而不是"把 637 行包进 `#ifndef`"：`open_with()` 在只读镜像里照样开文件，
句柄应当带着和读写镜像一样的 `path_hash` 不变量；把赋值去掉会让 `ofile_t` 的含义随构建
选项漂移。碰撞方向不受影响——哈希只用于"看起来是同一个文件就拒绝删除"，全树仍只有
`unlink_locked()` 读它。
