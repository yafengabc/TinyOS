## 判据

| 判据 | 结果 |
|---|---|
| 目标名不是芯片名 | `esp32c3-generic`；chip 仍是 `esp32c3` |
| 产物跟目标名 | `build/tinyos-esp32c3-generic.bin`、`-full.bin`、`tinyos-ramdisk-esp32c3-generic.bin` |
| WiFi 不靠目标名 | 链接条件改为板子的 `chip == "esp32c3"`，同一芯片的第二块板也能开 WiFi |
| 脚本默认路径仍有效 | `flash.py` 的 KERNEL/FS/FULL 全部解析到存在文件 |
| 镜像仍能跑 | RV32EMU-C：`filesystem: ok` + `SMOKE TEST OK`；C3 真机 24/24 |

## 做了什么

```text
board/esp32c3                     -> board/esp32c3-generic   (variant generic-esp32c3)
targets/esp32c3.conf              -> targets/esp32c3-generic.conf
build/tinyos-esp32c3.bin          -> build/tinyos-esp32c3-generic.bin
build/tinyos-esp32c3-full.bin     -> build/tinyos-esp32c3-generic-full.bin
build/tinyos-ramdisk-esp32c3.bin  -> build/tinyos-ramdisk-esp32c3-generic.bin
```

`configs/esp32c3*.conf` 保留文件名，内容 `target =` 改到 `esp32c3-generic`；CI 矩阵、
`FLASH-<target>.txt`、文档命令同步。芯片侧不动：chip 表、`chip = esp32c3`、
镜像格式 `(chip, arch)` 分派、`drivers/*/esp32c3`。

## 关于字节对比

改名前后的 C3 .bin **不再逐字节相同**：镜像里的板名从 `esp32c3` 变成
`esp32c3-generic`（+8 字节），后续代码地址整体平移，diff 会显示大量地址/偏移变化。
本轮没有把“字节相同”当判据，改用功能性证据：`tostest emu` 用 RV32EMU-C 启动
`kernel-esp32c3-generic.elf` + 新 ramdisk，输出 `filesystem: ok`、`SMOKE TEST OK`。
