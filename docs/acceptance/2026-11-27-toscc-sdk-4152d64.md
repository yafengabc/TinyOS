## 改名

`goc32` 听起来像“Go 语言的程序生成器”，而 `32` 也没有信息量（所有目标都是 32 位）。
二进制改为 **`toscc`**（TinyOS C compiler），和 `tos` / `tostest` / `tosput` 同一族。

- **没有改** Go module 和目录 `goc32/`：module 重命名要动 `go.mod` 和所有
  `goc32/internal/...` import，等大矩阵验收之后再单独做。
- `usage` 和错误前缀改成跟随 `argv[0]`，所以发布包里那份 `goc32` 别名仍然自称
  `goc32`（本机验证：`toscc -h` 打 `usage: toscc ...`，把同一个二进制复制成
  `goc32.exe` 后打 `usage: goc32 ...`）。
- tools 包（`tinyos-tools-*`）同时放 `toscc` 和 `goc32` 一份，保留一个版本；
  SDK 里只有 `toscc`。

## SDK 内容

`scripts/mksdk.py` 从 checkout 取用户程序真正读到的文件，加上 `toscc`：

```text
tinyos-sdk/
  bin/toscc[.exe]          bin/tosput[.exe]
  include/*.h              stdio.h、string.h、tos.h、tos_abi.h、...
  kernel/types.h           所有 include/*.h 的基类型
  user/                    lib.c、syscall.c、heap/aeabi/fix16/floatprint/
                           faeabi/softfloat32、thread.c、kthread.c、
                           thread_switch.S、crt0_{arm,rv32,x86}.S、
                           lib.h/heap.h/fix16.h/softfloat32.h、user.ld
  arch/{rv32,arm,x86}/usys.h
  examples/hello.c
  README.md
```

`kernel/types.h` 是必须的：`include/*.h` 全都从它开始；它同时也满足 `goc32`
查找 checkout 的标记（`user/lib.c`、`user/user.ld`、`include/tos.h`、`kernel/`），
所以 SDK 里不需要空的占位目录。

## 验证（本机，Windows）

```sh
python scripts/mksdk.py --out build/sdk \
    --toscc build/toscc.exe --tosput build/tosput.exe \
    --version v0.5.0-pre --archive build/tinyos-sdk-windows-amd64.zip
```

把 zip 解到仓库**外面**再跑（证明不依赖 checkout）：

```text
tinyos-sdk> bin\toscc.exe -target esp32c3 -o hello.tos examples\hello.c
hello.tos: 1793 -> 1214 bytes (LZ4TOS, hint 4096/0/0)
tinyos-sdk> bin\toscc.exe -target rp2350 -o hello-arm.tos examples\hello.c
hello-arm.tos: 1601 -> 1213 bytes
tinyos-sdk> bin\toscc.exe -target rp2040 -o hello-m0.tos examples\hello.c
hello-m0.tos: 1905 -> 1470 bytes
```

端到端（C3，默认 `esp32c3-generic` 镜像，COM4）：

```text

verified: 1242 bytes, crc32 cfc8f92d
tos> hello-sdk

  argv[0] = "hello-sdk"
```
