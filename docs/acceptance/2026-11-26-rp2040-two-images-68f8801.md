| 镜像 | 首遍 accept | `soak_board -m 30` | 浸泡后 accept | cycles |

| `rpi-pico` | ACCEPT OK 30/30 | PASS | ACCEPT OK 30/30 | 116 |
| `rpi-pico-smp` | ACCEPT OK 30/30 | PASS | ACCEPT OK 30/30 | 91 |

命令原文：

```sh
python scripts/rp2040/accept.py --uf2 build/tinyos-rpi-pico.uf2 -p auto
python scripts/rp2350/soak_board.py -p COM29 -m 30 --image rpi-pico -l build/soak-rpi-pico.log
python scripts/rp2040/accept.py -p COM29 --dtr
# smp 同上，镜像名换 rpi-pico-smp
```

`free` 前后除峰值水位一致，`deep 3` 每次 `stack grown` + `journal intact`，
`piperace` 全 ok，无 panic。SMP 第一次浸泡判定 FAIL 是 harness 读取窗口问题：
cycle 43 打出 `piperace: otos> k`，最后一个 `k` 落在提示符之后、`read_until()`
0.25 s 尾部窗口之外，于是统计 105/106。`68f8801` 把窗口扩到 0.75 s，重跑
30 分钟得到 91 cycles 全 ok；判据没有放宽。

## T3：#66 / #67（不能关闭的两项）

两个镜像的 `accept.py` 都是 `ACCEPT OK 30/30`、`/proc/ktask` 都有
`0 4096 <size>/<used> usbpump`（UP 232、SMP 284）、`ps` 的 `stk/sz` 分母为 4 KiB。
SMP 经 UART0 COM20 抓到启动日志：

```text
TinyOS - a tiny multi-platform operating system
[usb] pump thread pid 1 on cpu 0
TinyOS shell (pid 2).
```

但 issue 判据里还有两条不满足：

1. `kthreadtest` 两个镜像都是 `FAILED (1 failure(s))`，失败项
   `the holder died on its fault`。RP2040 的 Cortex-M0+ **没有 MPU**
   （`board/rpi-pico/platform.c` 明确说明，`plat_task_protect` 在
   `arch/arm/platform.c` 是空实现），`user/kthreadtest.c:75` 的
   `*(volatile int *)0 = 1` 在 U 态不会 fault，线程以正常退出码结束。
   这是测试前提不适用于平台，不是内核回归；已在 #72 留评论，未改测试、未加 skip。
2. `wheap` 实际输出是 `12 KiB declared, 12 KiB taken`，而 #66/#67 写的是
   32 KiB 窗口。需要确认是 issue 判据写错还是镜像配置缺项，我没有擅自改判据。

UP 镜像没有重新刷机抓启动日志（那会再要一次人工 BOOTSEL）；SMP 的日志已证明
同一固件族的泵线程启动路径。两项都应在 #66/#67 里明确记 `NOT RUN` / 不达判据。

## 工具坑

- `accept.py --uf2` 原先在 BOOTSEL 状态找串口，找不到 CDC；`a24b94d` 改成先刷机、
  再轮询端口最多 15 s，两个镜像都靠它刷入并得到 30/30。
- 一次被安全策略拦下的内联脚本在写入 `reboot` 后才报错，导致 RP2040 重启后
  CDC 没有回来（COM29 消失）；**不是用户拔线**。之后改用 UART0 COM20 抓日志。
- RP2040 的 Ctrl-D 进不了 BOOTSEL，刷机仍需人工按住按钮插拔 USB。
