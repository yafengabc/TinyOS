## 根因（两段）

1. **链接走了 clang → gcc**。发行版 clang 18 没有自己的 i386-elf 链接器，`-fuse-ld=lld`
   被转交给 `/usr/bin/gcc`，gcc 按发行版默认加上 `-pie`；`-no-pie` 是 clang 的车夫
   参数，**不会**转发给 gcc。结果是 static PIE，ld.lld 拒绝引导扇区的
   `R_386_16`/`R_386_32`（对本地符号）。
   修法：x86 的 `LD` 改成裸 `ld.lld -m elf_i386`（与 arm/rv32 一致），链接辅助函数
   本来就会在裸链接器下不加 `-Wl,` 前缀。
2. **预算**：修好链接后发行版 clang 18 产出 94012 字节内核，而引导扇区只读 180 扇区
   （92160）。本机 clang 23 更小，所以这一条只在别人的机器上出现。
   修法：`KERNEL_SECTORS` 180 → 200（100 KiB），littlefs 从 LBA 181 移到 201；
   `boot/stage1.S`、`internal/build` 与 `board/pc/layout.c` 三处一起改，构建期交叉校验。
