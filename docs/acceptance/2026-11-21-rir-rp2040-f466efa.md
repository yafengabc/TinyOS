## 板上链路（整数 / 字符串 / 浮点）

三个用例的源放在镜像的 `/src`（`files.local/src`，不提交），命令与输出：

```text
csc /src/arith.c /arith.rir      csc: /src/arith.c -> /arith.rir
rcc /arith.rir /bin/nd-arith     rcc: 2424 text, 2688 elf, 2728 tos, 131 labels
nd-arith                         -3 -2 17 9 20 14 2 -14 -2

csc /src/strings2.c /strings2.rir
rcc /strings2.rir /bin/nd-strings2   rcc: 3020 text, 3348 elf, 3391 tos, 168 labels
nd-strings2                      ab | hello | 0 | (空) | -1 | (空) | 0 | (空) |
                                 abc | abcZ | 42 | (空) | -7 | (空)

csc /src/float3.c /float3.rir
rcc /float3.rir /bin/nd-float3   rcc: 2556 text, 2816 elf, 2856 tos, 137 labels
nd-float3                        -0.75 3.75 -3.375 -0.6667 -1.5 1 1 3 -1.25
```

三份输出与 `build/thumb1/expected/*.txt`（由宿主 `rvm` 产生）**逐行一致**，包括
Q16.16 的 `-0.6667` 与字符串用例的空行。

## 窗口（`scripts/elfwin.py`，本卡新增该工具）

`#39` 把 `elfwin.py` 列为证据，但两仓里都没有这个文件。新增 `scripts/elfwin.py`：
按内核实际用的口径（`exec()` 里 `max(span, raw_size) + stack + heap + guard`，
再按 grain 向上取整）从 ELF 的 `PT_NOTE`（name `TinyOS`, type 1=stack 2=heap）读数。

```text
rcc    span 80.0 KiB  stack 16.0 KiB  heap 0  guard 4 KiB  -> window 100.0 KiB
csc    span 108.0 KiB stack 16.0 KiB  heap 0  guard 4 KiB  -> window 128.0 KiB
rvm    span 32.0 KiB  stack  8.0 KiB  heap 0  guard 4 KiB  -> window  44.0 KiB
用户区 PLAT_APP_MAX - PLAT_APP_BASE = 0x2000c000..0x20042000 = 216 KiB
```

**这就是"分时运行"的算术依据**：`csc`(128) + `rcc`(100) = 228 KiB > 216 KiB，两者
无法同时驻留；而 `rcc`(100) + `rvm`(44) = 144 KiB 可以。所以镜像里三个工具都作为
文件存在，由 shell 一次跑一个。

## 已知边界（不是本卡失败）

- 板内 `csc` 编 `hugeir.c` 报 `AST full at line 40`：与 `OPEN-ITEMS.md` §12 记的
  256 节点上限一致（`bigbody` 需 512）。大体量用例继续走宿主 `csc`。
- 板内 `rcc` 的上限约 2000 IR（§12）；本卡三例分别 131/168/137 个标签。

## 结论

RP2040 上可以**板内自编译**：`csc -> rcc -> exec` 三例与 `rvm` 一致，工具窗口与
216 KiB 用户区的关系清楚，`rcc` 走 Thumb-1 后端（`[target] rcc_arch`）。
`configs/rpi-pico-rir.conf` 是 test-only 镜像，任何发布配置都不要打开 `rir`。
