## 根因

不是内核、不是 QEMU、也不是窗口太短。`tostest` 的 `markSent()` 在**写串口前**把搜索
起点设为缓冲区末尾；上一条命令的 `tos> ` 可能还在 pump 里没读出来，落在 mark 之后。
于是下一条命令的 `waitFor("tos> ")` 立刻匹配到**上一条的 prompt**，驱动以为命令结束
并写入下一条；下一条的回显因此插进上一条输出。soak 数 `deep`/`piperace`/`free`
的时候正好少一个 cycle。

`a8d55b7` 把窗口放宽只能改变“真超时”的频率，改不了“匹配到旧 prompt”这条路径，所以
症状还在。

## 改动

```text
cmd/tostest/serial.go   waitForMark()：匹配后 mark = 匹配末尾；waitFor 逻辑共用
cmd/tostest/smoke.go    每条命令先 waitForMark(cmd) 等回显，再 waitFor("tos> ")
cmd/tostest/serial_test.go  TestWaitForMarkConsumesTheCommandEcho
```

未采纳“失败 cycle 自动重试一次”：那会把真正的间歇 bug 一起吞掉。现在同步点是
确定的，失败就是失败。

## 判据

| 判据 | 结果 |
|---|---|
| 上一条 prompt 不会再被当成这一条的 | 回归测试：只有旧 prompt 时必须不匹配 |
| 正常 smoke 不受影响 | 4/4，无 `no echo` / `no prompt` |
| soak 不再假 FAIL | 连续三次 `rv32,rv32smp,arm` 均 3/3 PASS |
| 失败仍然会报出来 | 回显缺失打印 `smoke: no echo of "<cmd>"`；prompt 缺失保留原报错 |
