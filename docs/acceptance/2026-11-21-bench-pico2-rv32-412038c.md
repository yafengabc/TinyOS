## 命令

```sh
python -u scripts/bench/compare.py -p COM27 --dtr --engine rcc --rvm
```

修复前同一命令三个工具都报 `exec: ... carries a bad stack hint`；#44 把 RV32 窗口
grain 提到 16 KiB 并让 PMP 窗口表逐级降级后，`csc → rvm → rcc → benchc` 全通。

## 结果（ms；校验和 46368 / 999850000 / 225792000 / 599994 全部一致）

| 内核 | rvm | rcc | 加速比 | M33 rcc（同板） |
|---|---:|---:|---:|---:|
| fib | 281 | 61 | 4.6× | 70 |
| loop | 397 | 27 | 14.7× | 44 |
| array | 803 | 60 | 13.4× | 120 |
| div | 352 | 42 | 8.4× | 47 |

`rvm` 两侧基本持平；`rcc` 的 RV32 后端（`rcc.c` 的 `RCC_ARCH_RV32`）在这组内核上
比 Thumb-2 更快，尤其 `array` 60 vs 120 ms。

## 没做（NOT RUN）

- `micropython` / `@native` / `pvm` / `goc32` / `clang` 五列（见 M33 卡片同样说明）；
- 多次重复取中位数（本表为一次运行；M33 卡也是一次运行，口径一致）。

板子当前停在这份 RV32 rir 镜像（工具可用）。
