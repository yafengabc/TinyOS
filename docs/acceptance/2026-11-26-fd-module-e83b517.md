## 接缝（只搬代码，语义不变）

- `fd.c` 通过 `proc_fd_table/proc_fd_lock/proc_fd_unlock` 拿表和锁，通过
  `process_pipe_closed(p, write_end)` 处理“最后一方关掉管道”——唤醒对端、必要时
  `kfree`；`process_pipe_ready(p, write_end)` 只服务 poll。这五个都在 `process.c`
  实现，因为 `pipe.h` 的约定是“谁可以碰任务只有 `process.c`”。
- `read()`/`write()` 与 `pipe_deliver_locked`/`pipe_wake_locked`/`block_on_pipe_locked`
  留在 `process.c`：它们要挂起/唤醒线程。
- `fd_slot`、`fd_clone`、`fd_close_in` 仍是 static 语义的三个入口，现在跨文件，
  声明在 `fd_internal.h`；`exec` 的继承和 `task_release` 的关闭都用它们。
- 锁范围逐处核对：`fd_close_in` 原来在管道分支里自己取 `proc_lock`，现在由
  `process_pipe_closed` 取同一把锁，包裹同样的 drop/判断/wake；free 仍在锁外。
