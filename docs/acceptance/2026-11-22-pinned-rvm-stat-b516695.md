## 问题

`tinyos-script` 的 40ab506 为 Linux CI 把 host shim 的 stat 结构改名
`struct tos_stat`（glibc 的 `<fcntl.h>` 已占用 `struct stat`），并同步改了
`src/rvm.c`。pin 到 TinyOS 后，目标端用的是 `user/lib.h`，那里只有
`struct stat`（`include/tos_abi.h`），于是所有含 rvm 的镜像编译失败：

```text
user/rvm/rvm.c:645:37: error: variable has incomplete type 'struct tos_stat'
```

脚本仓库自己的测试看不到这个问题：`tools/test.py` 用它自己的
`include/lib.h` 编译；TinyOS 的 `TestPinnedToolchainSources` 只比较字节，不编译。

## 处理

布局一致（`size` + `type`），在 `user/lib.h` 加一行 tag 别名：

```c
#define tos_stat stat
```

已在上游脚本仓库建议更干净的后续：两边共用一个中性类型（`tos_stat_t`），
并在 CI 里把 pinned 副本按 TinyOS 的 `user/lib.h` 编译一次。
