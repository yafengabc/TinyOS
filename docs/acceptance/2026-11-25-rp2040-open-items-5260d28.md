```

```

```

```

前 7 项（boot/identity/clock/heap/ls/exec/write-back/cwd-exec）全 PASS，长输出等后续项因脚本在此中断未跑到。

**这项 FAIL 不是板子的 fault 逻辑问题**，证据（UART0 上 3 轮重复，`tmp/rp2040_crash_uart_diag.py`）：

```
round 1: before=366.412s after=370.437s prompt_in_crash=True panic=False
round 2: before=373.561s after=373.647s prompt_in_crash=True panic=False
round 3: before=376.773s after=376.981s prompt_in_crash=True panic=False
  crash out: [pid 43] HardFault at 0x2001409a
             lr=0x2001405f xpsr=0x61000000 hw=0x20017eb8 exc=0xfffffffd
```

SMP 上 crash 正常打印 HardFault 现场、回到提示符、uptime 连续不复位（366→370→373→376 s），与 CDC 路径的 FAIL 无关。CDC 路径的现象是：crash 触发的非法指令异常输出（含多行寄存器转储）经 CDC 送出期间，测试脚本 10 s 内没读到结尾提示符；同一时段 COM29 反复出现 `PermissionError 5`（串口句柄泄漏，物理重插前一直不可用）。判为 **CDC 输出/串口可靠性问题，板级 fault isolation 本身 PASS**（UART0 为证）。

## §5c(c) tosput gap=1 ms 实验

`tmp/rp2040_gap_experiment.py`：临时把 `tools/tosput/sender.go:122` 的 `const gap = 2 * time.Millisecond` 改成 1 ms，编译 `tosput-gap1.exe`，42 KiB / 128 KiB 各传 3 次，**finally 恢复 sender.go**（已确认 `git status` 无残留、gap 回到 2 ms）。

| size | round | rc | NAK | CRC | dropped(D) | handed(H) | 结果 |
|---|---|---|---|---|---|---|---|
| 42 KiB | 1/2/3 | 0 | 0 | pass | 2038 / 2748 / 3458 | 836 | 数据通过，D 增长 |
| 128 KiB | 1/2/3 | 0 | 0 | pass | 4886 / 6314 / 7742 | 836 | 数据通过，D 增长 |

判据要求 `NAK=0 && CRC pass && D=0`：前两条满足，**D=0 未达成**。D 随每次传输等量增长（42 KiB ≈ +710，128 KiB ≈ +1428），符合 §5c(c) 对 `D>0` 的判读——**环满（时序不够）**，不是 TTL/FIFO 侧丢失。结论：当前 2 ms gap 是必要值，降到 1 ms 会把输出挤进丢弃区。实验值未提交。
