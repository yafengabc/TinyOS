## T2 — QEMU

```sh
for t in rv32 rv32smp arm; do go run ./cmd/tostest smoke -target $t \
  -commands "ps, ls /bin | wc, cat /proc/execfmt, piperace, prot stack, deep 3, rselftest" \
  -commandwait-ms 4000; done
python scripts/soak.py --cycles 3 --targets rv32,rv32smp,arm
```

- smoke：3/3 `SMOKE TEST OK`；`piperace: ok` 在 rv32smp / arm 有，rv32 没有。
- soak 首次：`rv32 FAIL, rv32smp PASS, arm PASS`（2/3）。

追查后**不是内核问题**：rv32 单核上 `piperace`（64 KiB，2 KiB 环）要跑很久，
`-commandwait-ms 4000`、20000 都不够，90000 时 `piperace: ok` 正常返回；
`soak.py --targets rv32 --commandwait-ms 60000` → **PASS**。

```text
rv32     PASS  tasks      19988480     19520  (3 cycles)
rv32smp  PASS  tasks      19988480     19520  (3 cycles)
arm      PASS  tasks       3342336      3264  (3 cycles)
```

**顺带发现一个假绿**：`cmd/tostest/smoke.go` 在 `len(timedOut) > 0` 时只打印
`--- smoke: N command(s) never echoed a prompt: ...`，仍然返回 nil、仍然打印
`SMOKE TEST OK`。上面那次 rv32 有 **27 条命令从未执行**，结论却是 OK。这会让
任何一次“绿”都失去意义；建议改成非零退出（或用默认 4 s 的调用全部显式给足等待）。
本次未改，因为它会翻转 CI 现有判定，需要发布负责人拍板。

## T3 — 真机（ATK-DNRP2350AM，UART0 COM14）

板子只有 ATK 在线（Pico 2 / RP2040 / C3 未接）。按建议把 **Pico 2 的镜像刷到同一块
ATK 上**跑：#74–#77 的镜像都是 RP2350，控制台同样落在 UART0（GP0/GP1，ATK 的 CH343），
`littlefs` 由 JEDEC 探测按实际 4 MiB 自适应（`df` 3,670,016），所以用
`accept33 --df 3670016` 判。**这不是 Pico 2 实物验证**：Pico 2 的 8 MiB flash 与板级
外设（LED 引脚等）没有覆盖。

| 镜像 | accept33（`--dd-rounds 100`） | kthreadtest | 备注 |
|---|---|---|---|
| atk-dnr2350am-smp | 21/21 | — | smpbench 2.02x |
| atk-dnr2350am | 19/19 | — | |
| atk-dnr2350am-rv32-smp | 22/22 | — | |
| atk-dnr2350am-rv32 | 20/20 | — | |
| rpi-pico2 | 20/20 | all ok (0) | |
| rpi-pico2-smp | **22/22** | all ok (0) | smpbench 1.98x；dd+rm 100 轮 PASS |
| rpi-pico2-rv32 | 21/21 | **FAILED (1)** | 见下 |
| rpi-pico2-rv32-smp | 23/23 | **FAILED (1)** | smpbench 1.90x |

RV32 两张的失败项是同一条：

```text
kthreadtest: FAIL the holder died on its fault
```

`/proc/cpuinfo` 报 `memprot: on`，所以 `kthreadtest` 走严格分支，要求线程写地址 0 后
以 139 退出；实际线程正常退出。这条就是 **#72**（“no-MPU ports … and Pico 2 RV32”），
至今 OPEN。RV32 端 `plat_has_memprot()` 无条件返回 1（`arch/rv32/platform.c:218`），
而地址 0 实际没有被 PMP 拒掉——要么让 PMP 覆盖它，要么让能力上报说真话。

## 发布结论

可以发 0.5.0 的部分：T1、T2、T3 的 accept 全绿，T4（SMP 浸泡）绿。

**阻塞项**

1. **#72 / RV32 kthreadtest**：`rpi-pico2-rv32` 与 `-rv32-smp` 各 1 failure → #76、#77
   按判据不能关闭。
2. **T0 pinned 工具链**：`tinyos-script` 侧落后于本仓库（缺 `yield`/`ready`），需要在
   那个仓库补一次提交，否则本机 T0 永远红一条。
3. **`smoke` 假绿**：命令没执行也报 OK，建议在发布前修掉（否则“绿”不可信）。

**明确 NOT RUN**

- 真实 Pico 2 硬件（本次用 ATK 代跑镜像）、RP2040（#66/#67，无板）、ESP32-C3（未接）、
  ATK 的 `-rv32` UP 的 T4（非 SMP，按 TESTING.md §6 不跑）。
