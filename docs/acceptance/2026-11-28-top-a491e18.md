## 用法

```text
tos> top                 # 每秒刷新，直到 ^C
tos> top -d 200          # 200 ms 一次
tos> top -n 5 -d 500     # 刷新 5 次后退出
tos> top -n 1 > /f       # 快照写文件（走 /proc/ps，不直接写控制台）
```

板上输出：

```text

   1    1    0    1 wait  -    0.9     0   24    1.3/4  sh

```

## 设计取舍

- **不抢光标**：`kernel/tty.c` 不解析 ANSI 转义，清屏/定位是内核改动，不是
  一个工具该做的事；每次刷新打印分隔头和表，终端自然滚动。
- **读 `/proc/ps` 而不是 `ps()`**：`ps()` 直接写控制台，重定向会失效；
  `/proc/ps` 走 fd，`top > f` 才能写文件（和 shell 的 `ps` 内建同一路径）。
- **单独程序，不进 `tools`**：`tools` 在 rv32 上距 12 KiB span 只剩 192 B，
  而 `top` 会长时间占着窗口。实测 `top` 是 **4 KiB span / 12 KiB 窗口**，
  设备上 1,604 B。
- **^C**：shell 的前台作业收到 `SIGKILL`，`top` 不需要信号处理；实测
  `[pid 7] killed` 后立刻回到提示符。
- `-d` 下限 10 ms（低于一个 tick 只会空转），上限与 `sleep` 一致 3600000 ms。

## 验证

- `top -n 2 -d 200` 两次刷新、`top -n 1 > /f` 后 `cat /f` 内容一致；
- 非法参数打印 `usage: top [-d ms] [-n count]`；
- `^C` 终止并回到 `tos>`；
- T0/T1 18/18/T2 smoke 三架构/C3 accept 42/42。

## 没有做的

- 排序/过滤（按 CPU 排序需要解析 `/proc/ps` 的定宽表；先不加）；
- 清屏（需要内核 tty 支持 ANSI，或走 screen 设备）；
- `top` 目前不在 `release.conf` 的排除表里，发布镜像会带上它（约 4 KiB block）。
