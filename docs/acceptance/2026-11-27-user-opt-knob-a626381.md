## 为什么

`compile()` 先加 `b.ccFlags()`（含内核 opt），再追加用户 flags，所以 **`TOS_OPT`
会作用到每个 C 文件**，用户程序也一样；`user/<prog>/opt` 因为更靠后才覆盖它。
结果是“内核 `-Oz`、基准 `-O2`”这种隔离做不到——这正是 `-Oz` 的 CoreMark
478→289、smpbench 2.00→1.75 的问题：**基准自己也被换了优化级别**。

## 优先级

```text
TOS_USER_OPT  >  [build] user_opt  >  [target] user_opt  >  （空：继承内核）
                                                          单程序 user/<name>/opt 永远最后，覆盖以上
```

## 验证

- rv32，`TOS_OPT=-Oz` + `user_opt = -O2`：内核 `.text` **56,898**（纯 `-O2` 是 71,732），
  而 `hello`（496）与 `coremark`（8,838）与纯 `-O2` 构建**逐字节同尺寸**；
- `msh` 仍按自己的 `opt = -Oz`（4,068），不受 `user_opt` 影响；
- `build-config.txt` 现在两行：

  ```text
  opt         -Oz (kernel)
  user_opt    -O2
  #   opt         TOS_OPT:-Oz
  #   user_opt    config:<path>
  ```

- 单元测试：`TestConfigUserOpt`（解析 + 拒绝非法值，`opt` 也补了校验）、
  `TestUserOptPrecedence`（env > config > target > 空）。

## 板上隔离测量（2026-11-27，ATK-DNRP2350AM，M33 SMP）

回答上面“板侧要补的一条”。三版内核都用 `TOS_USER_OPT=-O2`，用户程序因此
逐字节相同：`coremark` sha256 `d7eefb27…`、`smpbench` `91a80b68…`、
`threadbench` `a0e037df…`，三版一致（`build/uopt/K*/user.sha`）。

| 内核 `TOS_OPT` | `.text` | Total | CoreMark（5000 次迭代 ×3） | 总 ticks | smpbench single | dual wall | speedup |
|---|---|---|---|---|---|---|---|
| `-O2` | 144,000 | 281,208 | 478 / 478 / 478 | 10,454–10,457 | 37–38 ms | 38–39 ms | 1.89 / 1.94 / 2.00（6 轮均值 1.95） |
| `-Os` | 100,670 | 237,878 | **487 / 487 / 487** | 10,253–10,256 | 37 ms | 36–37 ms | **2.00–2.05**（6 轮均值 2.02） |
| `-Oz` | 88,128 | 225,336 | 476 / 476 / 476 | 10,490–10,494 | 37–38 ms | 40–41 ms | 1.85–1.90（6 轮均值 1.87） |

`threadbench`（3 线程 ×300000）：O2 14 ms / ratio 58%，Os 13 ms / 57%，Oz 13 ms / 57%；
`sw` 分别为 39 / 40 / 39。

### 结论

- **`-Oz` 内核本身只慢 0.4%（476 vs 478）**，但 SMP 扩展性掉到 1.85–1.90
  （O2 是 1.89–2.00，均值差约 4%）。1.8x 阈值能过，1.9x 稳定线过不去。
- **`-Os` 是这棵树上的最优点**：比 O2 小 43,330 B（−30%），单线程反而快 1.9%
  （487），SMP 2.00–2.05 也最好。`.bss` 三版相同（137,208）。
- 之前 `-Oz` 的 289 / 1.75x 全部是基准自己被 `-Oz` 编译所致；同内核换回 O2 基准
  即回到 476 / 1.85–1.90。`accept33` 那条 `smpbench 1.76x < 1.8x` 同理属于基准等级，
  不是内核。

### 测量口径

- 用 `coremark 5000`（固定迭代，约 10.3–10.5 s）而不是 auto：固定值同时满足
  “≥10 s”判据，且 `Correct operation validated`、`crclist/matrix/state` 均对上；
  auto 模式偶尔在 CH343 UART 上丢输出段（banner 后直接提示符），重跑即恢复。
- 每组 3 个有效样本，丢弃丢输出的轮次（`build/bench_retry.sh`）。
- 原始日志：`build/uopt/K{O2,Os,Oz}-uO2/`（本地，不入库）。

同期 C3 对照（`2026-11-27-c3-kernel-opt-user-bench.md`，用户 coremark 固定 `-O2`）
给出同样的结论：内核 `-O2` 346 vs `-Oz` 343–344 iter/s，差 <1%。两个端口都指向
「内核 `-Oz` 对纯用户计算几乎无损，代价主要在 SMP 扩展性」。
