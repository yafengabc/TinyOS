## 缺陷与复现

`resolve_path()` 把规范化结果写进 `TOS_PATH_MAX` 缓冲；放不下时 `path_segments()`
只是停止追加，syscall 接着在**另一个更短的名字**上执行。绝对路径超过 63 字节会先在
`copy_user_string()` 被拒，所以真正到得了这里的是**相对路径**（cwd + 名字超过缓冲）。

rv32 实测（旧代码）：

```text
tos> cd /tests
tos> ls
cover.c  ready.c  state.c
tos> echo hi > ccccccccccccccccccccccccccccccccccccccccccccccccccccccccc
tos> ls
cccccccccccccccccccccccccccccccccccccccccccccccccccccccc  cover.c  ready.c
state.c
```

57 个字符的请求，创建出来的是 55 个字符的文件（截断后的名字）。

## 修法与结果

- `path_segments()` 返回 int：`*no + 1 + len >= cap` 就 `-1`（分隔符和结尾都算在内）。
- `resolve_path()` 透传失败；`do_exec()` 与六个 switch 分支（open/create/unlink/
  listdir/stat/chdir）失败时返回 `-1`。
- 同一命令在修复后：

```text
tos> cd /tests
tos> echo hi > ccccccccccccccccccccccccccccccccccccccccccccccccccccccccc
sh: cannot write to ccccccccccccccccccccccccccccccccccccccccccccccccccccccccc
tos> ls
cover.c  ready.c  state.c
```

- 正常长名字不受影响：`/tests` 下 40 字符的名字仍可创建、读回 `hi`、删除。
