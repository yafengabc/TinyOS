notes:
- csc's old `Func` was 340 B (75% `params[8][32]`), so 32 functions already cost
  10.9 KiB and raising it naively was not an option on the board.  The table is
  now `Sig` (20 B: name offset, entry pc, nparams, rtype, rstruct, ptype[8]) plus
  an 8-byte name pool per function; parameter names are re-read by pass 2 into
  one scratch array.  256 board / 1024 host functions cost the same BSS as the
  old 32, so the C3 `csc` window is unchanged at 126976.
- rcc board limits are now RIR_MAX 40960, PC_MAX 2048, LABEL_MAX 4096,
  TEXT_MAX 49152, FUNC_MAX 256.  pc_label became uint16 with a 0xFFFF
  sentinel (4 KiB of ints bought 2x the PCs).  The summary line gained a label
  count (`rcc: N text, N elf, N tos, N labels`), which is what exposed the
  1.45 labels/IR cost of `%` and the old 768-label ceiling.
- Board windows after the change: csc 126976 (unchanged), rcc 122880 (was
  73728), rvm 32768 (unchanged).
- New cases, all native-only because they exceed rvm's 256 IR:
  `many100` 111 functions / 898 IR / 24232 text / 1208 labels (the UFCS shape,
  grouped so no caller exceeds the board AST budget); `bigir` 29 functions /
  1436 IR / 17292 text / 2062 labels (board-compilable end to end except that
  the board csc hits AST full, so its RIR2 is host-generated); `hugeir` 31
  functions / 2948 IR / 29556 text (host rcc only).
- C3 end-to-end: `csc /many100.c` -> `rcc` -> 20009 on the board, proving the
  256-function table and 1208 labels on hardware.  `rcc /bigir.rir` ->
  2062 labels, printed 1325.  Both match the host gcc reference.
- QEMU rv32: same chain (`csc /many100.c` -> `rcc` -> 20009; `rcc` on
  bigir.rir -> 1325), plus the two staged .tos printing 20009 / 1325.
- Trap found and documented in port/tinyos/README.md: PowerShell `Copy-Item`
  preserves the source mtime, and TinyOS only recompiles a newer source.  The
  first board run still had the 32-function csc while `user/csc/csc.c` already
  had 256.  Touch the destination after copying.
